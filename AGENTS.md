# Repository Guidelines

## Project Structure & Module Organization
Keep the layout from `Transition Docs/TRANSFORMATION_MASTER_PLAN.md`: `calculations/` is the source-of-truth engine that reads `data/` and feeds `main.py` + `output/` exports. `shared/types` and `shared/calculator` hold the TS contracts regenerated by `scripts/generate_vehicle_catalog_ts.py` for `frontend/src` and `backend/app`. `scripts/` also carries `export_tco_snapshot.py` and `validation.py`, `analysis/` holds policy studies, and Docker assets keep the Postgres/Redis topology reproducible.

## Build, Test, and Development Commands
- `python -m pip install -r requirements.txt && pre-commit install` primes Python tooling.
- `python main.py` plus `analysis/generate_tco_analysis.py` regenerate CSV/Plotly exports promised in the plan.
- `python scripts/generate_vehicle_catalog_ts.py` and `python scripts/export_tco_snapshot.py` refresh the shared SDK before frontend or API work.
- `uvicorn backend.app.main:app --reload` boots FastAPI; `docker-compose up --build` exercises the full Postgres/Redis stack.
- `cd frontend && npm install && npm run dev` starts the wizard, while `npm run build|lint|typecheck` satisfy CI gates.
- `python -m pytest tests --cov` and `npm run test -- --runInBand` enforce the ±1 % parity budget; add `-n auto` when `pytest-xdist` is installed.

## Coding Style & Naming Conventions
Python files use 4-space indents, type hints, and Google-style docstrings; run `ruff check .`, `black .`, and `isort .` pre-push. TypeScript remains in strict mode with ESLint/Prettier defaults (2-space indent, single quotes). Keep components `PascalCase`, hooks `useCamelCase`, and import DTOs from `shared/types` to keep every layer on the same contract.

## Testing & Parity Guidelines
`tests/test_comprehensive.py` anchors financing, operating, and scenario checks—extend it or add focused `test_*.py` modules rather than duplicating fixtures. Run `python scripts/validation.py` whenever vehicle, scenario, or policy data changes, and seed Monte Carlo helpers for reproducible CI. Keep the shared TypeScript calculator and Vitest suite within ±1 % of the Python outputs, and include parity evidence with each PR.

## Commit & Pull Request Guidelines
Commits stay concise and imperative (“Add web app backend, frontend, and shared packages”), stay under 72 characters, and tag subsystems (`backend:`, `frontend:`, `shared:`). PRs should describe scope, list executed commands (pytest, Vitest, lint, exports), flag schema or data migrations, attach artefacts when UX or CSV outputs change, and request reviewers from each affected discipline.

## Security & Configuration Tips
Use `.env.example` as the template for secrets; load variables via `python-dotenv`/`pydantic-settings` so FastAPI, scripts, and Docker read the same source. Never commit operator data or credentials inside `data/` or `frontend/public`. Run `pip-audit`, `npm audit`, and `bandit` whenever dependencies move, regenerate shared types when `data/*.py` changes, and record material data revisions in `Transition Docs/TRANSFORMATION_EXECUTION_LOG.md`.
